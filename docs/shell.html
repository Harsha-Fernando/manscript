Project tools on demand

Development shell

manscript shell opens an interactive child shell in the project root. Managed project tools come first on that child's PATH; your original terminal is not modified.

The entry summary labels the project, stack versions, and environment, then shows a Ready section before handing control to the child shell. The prompt itself may still look unchanged because zsh, bash, or another shell can replace ManScript's suggested prompt from its startup configuration.

Prepare the project first

The command requires both manscript.toml and a ready project environment.

cd /path/to/project
manscript setup
manscript shell

Setup is normally already complete after manscript create. Run it after cloning a configured project because `.manscript/environment` is not normally committed.

What changes in the child

Project languageChild-shell behavior
PythonPrepends `.manscript/environment/bin` (or the Windows equivalent), exposing the environment's Python, pip, and installed scripts.
RubyPrepends project and Ruby gem bin directories and sets GEM_HOME, GEM_PATH, BUNDLE_PATH, BUNDLE_BIN, BUNDLE_GEMFILE, and, when available, RUBY_ROOT.
C and C++Prepends the project tool bin containing shims to the system compiler detected during setup.
JavaPrepends project shims for the detected system javac and java.
GoPrepends the mapped go tool and sets project-local GOMODCACHE, GOCACHE, and GOPATH.
RustPrepends mapped rustc and cargo tools and sets project-local CARGO_HOME and CARGO_TARGET_DIR.
PHPPrepends mapped PHP/Composer tools and vendor/bin, and sets project-local COMPOSER_HOME.
C#Prepends the mapped dotnet tool and project .NET tools, and sets project-local NUGET_PACKAGES and DOTNET_CLI_HOME plus noninteractive CLI defaults.

Existing PATH entries and inherited environment variables remain after the prepended entries. Changes are passed through the child process environment only. ManScript does not call activation scripts, edit `.zshrc`, `.bashrc`, profiles, or change the parent process.

Prompt and shell selection

On Unix and macOS, ManScript launches the executable named by SHELL, falling back to /bin/sh. It supplies a sanitized PS1 based on the project name on Unix only. Your shell may replace that prompt from its own startup configuration.

On Windows, ManScript launches COMSPEC, falling back to powershell.exe. It does not set PS1 there.

MANSCRIPT_SHELL is an explicit diagnostic/test override for the executable path. It is not parsed as a command string and cannot contain shell arguments.

Working in the shell

# Python example
which python
python --version
pip list

# Ruby example
which ruby
bundle exec rails routes

Commands entered interactively are handled by your chosen shell. They are therefore outside the restricted argv model used for commands from manscript.toml. Review any command before running it.

Exit and EOF

Type exit or send your shell's EOF keystroke (commonly Ctrl-D on Unix) to close the child. After a successful exit, ManScript prints:

Development shell closed. Your original terminal environment is unchanged. Goodbye.

If the child shell exits with a non-zero status, ManScript returns that status instead of reporting a successful close.

Recover from common errors

No ManScript project

Change into a directory containing manscript.toml, or a child directory. For an existing unconfigured project:

manscript init
manscript setup
manscript shell

Environment not ready

manscript setup
manscript shell

If setup fails to detect a runtime, compiler, or JDK, follow the troubleshooting guide. Use manscript env to inspect the paths ManScript resolved.
