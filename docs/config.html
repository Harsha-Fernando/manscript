Reference

manscript.toml

The configuration file describes one project. ManScript searches for it from the current directory upward, so commands also work from project subdirectories.

Complete example

name = "myproject"

[language]
name = "python"
version = "3.13"

[framework]
name = "django"
version = "5.2"

[environment]
manager = "venv"

[runtime]
provider = "system"

[commands]
run = "python manage.py runserver"
test = "python manage.py test"
build = "python -m compileall ."

Language-only projects omit the entire [framework] section. Optional sections and command keys may also be omitted.

Schema

KeyTypeRequired?Meaning
namestringYesHuman-readable project name and child-shell prompt source.
language.namestringYespython, ruby, c, cpp, java, go, rust, php, or csharp.
language.versionstringYesRuntime version requirement used during detection and setup.
framework.namestringWith sectiondjango, fastapi, flask, rails, or sinatra.
framework.versionstringWith sectionConfigured framework version.
environment.managerstringNoRecords the adapter's environment strategy. Generated configs use venv, bundler, toolchain, composer, or dotnet. The selected language adapter controls the implementation; changing this value does not switch environment providers.
runtime.providerstringNoExplicit provider preference: system, uv, or mise where supported. If omitted, ManScript first detects a suitable system runtime, then offers the language's managed fallback after confirmation.
commands.runstringNoProgram and arguments for manscript run; run errors when absent.
commands.teststringNoProgram and arguments for manscript test; absence is a successful no-op.
commands.buildstringNoProgram and arguments for manscript build; adapters may provide build behavior themselves.

When omitted, [environment], [runtime], and [commands] deserialize to empty/default values. There is no separate lock-file schema in 0.1.5.

Command strings become argv

Configured commands look like shell text for readability, but ManScript does not run them through a shell. It splits the text into a program and arguments, resolves the program through the selected language adapter, and launches it directly.

run = "python -m uvicorn main:app --port 8000"

This becomes an argv sequence equivalent to ["python", "-m", "uvicorn", "main:app", "--port", "8000"]. Extra CLI arguments are appended literally:

manscript run --log-level debug

Quoting and escaping

  • Whitespace separates arguments outside quotes.
  • Single and double quotes group spaces and are removed.
  • A backslash escapes the next character outside single quotes.
  • Environment variables, globs, substitutions, and shell built-ins are not expanded.

Rejected input

ManScript rejects empty commands, unclosed quotes, sudo, program path traversal with .., and tokens containing |, ;, &, >, <, backticks, or $.

Configuration is still trusted

Direct argv execution reduces shell-injection risk, but a command can still run an executable and dependencies can run installation code. Review manscript.toml in an unfamiliar repository before setup or execution.

Storage locations

The project environment always lives under .manscript/environment. Go sets project-local GOMODCACHE, GOCACHE, and GOPATH; Rust sets CARGO_HOME and CARGO_TARGET_DIR; PHP sets COMPOSER_HOME; C# sets NUGET_PACKAGES and DOTNET_CLI_HOME. User-level downloaded tools live under ~/.manscript/tools by default. Set MANSCRIPT_HOME before running ManScript to move that user cache; it does not move project-local environments or caches.
