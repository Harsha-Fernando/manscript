Problem solving

Troubleshooting

Start with the read-only diagnostic command. Its recommendations are tailored to the tools ManScript can detect.

manscript doctor

WARN means ManScript can explain a recoverable condition and suggest a next step. ERROR means the requested command could not continue. For plain output without ANSI color, set NO_COLOR=1.

What doctor checks

Doctor reports the platform and ManScript version, then checks Python and its venv module, pip or uv, Ruby and Bundler, C and C++ compilers, javac, Go, Rust and Cargo, PHP and Composer, and the .NET SDK. When run inside a configured project, it also reports project identity and environment readiness.

Doctor reports system tools and remains read-only. A failed system-runtime check does not always block setup: Python can use uv, while Ruby, Go, Rust, PHP, and C# can use a confirmed mise-managed fallback. Compiler and JDK failures still block C, C++, and Java because ManScript does not download those toolchains.

manscript: command not found

  1. Confirm installation completed: cargo install --path .
  2. Open a new terminal.
  3. Confirm Cargo's bin directory exists and is on PATH.

zsh

export PATH="$HOME/.cargo/bin:$PATH"
manscript --version

bash

export PATH="$HOME/.cargo/bin:$PATH"
manscript --version

PowerShell

$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
manscript --version

These examples affect the current terminal. Add the equivalent line to your shell's user configuration only if you want it to persist.

“This folder is not a ManScript project”

ManScript looked in the current directory and each parent but found no manscript.toml.

New project

cd ..
manscript create

Existing project

cd /path/to/project
manscript init
manscript setup

Already configured

Change into the repository tree that contains manscript.toml.

“Project environment is not ready”

The project exists, but expected tools are missing from .manscript/environment. Prepare or repair it:

manscript setup
manscript env

Use setup after cloning because project environments are normally ignored by Git. install, run, test, build, and shell require the environment to be ready.

Python runtime or venv not detected

Run manscript setup. ManScript first looks for a suitable system Python and can use the uv provider to prepare an isolated Python runtime. If system Python exists but python -m venv fails, install the platform's venv support or allow setup to use an isolated runtime.

Ruby or Bundler not detected

Setup can prepare Ruby through mise and installs Bundler for the project when necessary. Ruby dependencies and Bundler state are isolated through .bundle/config and .manscript/environment.

manscript setup
manscript shell

Go, Rust, PHP, or .NET runtime not detected

Run manscript setup. Unless an explicit runtime provider is configured, ManScript checks for a suitable system runtime first, then asks before preparing a mise-managed fallback below MANSCRIPT_HOME. Use --yes only when you intend to accept that download noninteractively.

Rust also needs Cargo. PHP projects require a verified system Composer executable even when PHP itself comes from mise; install Composer using its official verified instructions and keep it on PATH. ManScript does not run an unverified Composer bootstrap installer.

go version
rustc --version
cargo --version
php --version
composer --version
dotnet --version
manscript doctor
manscript setup

Dependency setup fails

Setup and install directly run go mod download, cargo fetch, composer install, or dotnet restore. Read the package manager's error for registry, lock-file, manifest, or network details. Their module, package, build-cache, and CLI-state variables point below the project root, so check that the project is writable and has enough disk space.

C or C++ compiler not detected

Install a real system compiler and ensure cc or c++ is on PATH. On macOS, install Xcode Command Line Tools. On Linux, install GCC or Clang. On Windows, use LLVM or MinGW; a launcher stub that cannot compile is not sufficient.

cc --version
c++ --version
manscript doctor
manscript setup

Setup records project shims that point to the detected compiler; it does not copy or download a compiler.

Java or JDK not detected

Install JDK 17 or newer and ensure both javac and java are runnable. A JRE alone is insufficient.

javac -version
java -version
manscript doctor
manscript setup

Configuration errors

Check TOML quotes, section names, and required name, language.name, and language.version fields. See the complete schema. For a configured command rejection, remove shell syntax and express the operation as one directly executable program plus arguments.

Still stuck?

Capture manscript --version, manscript doctor, your operating system, and a redacted manscript.toml, then open an issue on GitHub. Do not post secrets or private vulnerability details.
