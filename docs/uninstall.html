Removal

Uninstall ManScript

The CLI, downloaded runtime cache, project environments, and shell completion setup are separate. Remove only what you no longer need.

1. Remove the CLI

cargo uninstall manscript

This removes the installed manscript executable from Cargo's bin directory. It does not remove source clones or project files.

2. Remove downloaded tools (optional)

ManScript stores user-level downloaded tools under ~/.manscript by default.

macOS and Linux

rm -rf ~/.manscript

Windows PowerShell

Remove-Item -Recurse -Force "$env:USERPROFILE\.manscript"

If you set MANSCRIPT_HOME, remove that directory instead. Check its value before deleting anything:

# macOS/Linux
printf '%s\n' "$MANSCRIPT_HOME"

# PowerShell
$env:MANSCRIPT_HOME

3. Remove project environments (optional)

Each configured project keeps its isolated environment under .manscript/environment. Go, Rust, PHP, and C# also keep redirected module, package, build-cache, or CLI state under the project's .manscript directory. Removing that directory preserves source and manscript.toml; a later manscript setup can recreate it. Language-owned output elsewhere in the project, such as PHP's vendor/, is not removed automatically.

macOS and Linux

rm -rf /path/to/project/.manscript

Windows PowerShell

Remove-Item -Recurse -Force "C:\path\to\project\.manscript"

4. Remove completion setup (optional)

If you added an eval "$(manscript completions …)" line or sourced a generated completion file from your shell startup configuration, remove that line or file. ManScript did not add it automatically.

Typical files include ~/.zshrc, ~/.bashrc, fish configuration, or your PowerShell profile. Do not delete the whole startup file.

What remains

Uninstalling ManScript does not remove Python, Ruby, C/C++ compilers, Java, Go, Rust, PHP, Composer, the .NET SDK, application source, or packages outside ManScript's own project/cache directories. Remove rustup separately only if you no longer use Rust; see the rustup uninstall documentation.
