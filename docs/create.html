Projects and generators

Create

manscript create starts a project when no manscript.toml is found. Inside a ManScript project, it adds something supported by that framework instead of nesting another project.

Start a new project

manscript create
  1. Choose Python, Ruby, C, C++, or Java.
  2. For Python or Ruby, choose a framework or None. C, C++, and Java skip this prompt because each has one project kind.
  3. Enter the new folder name.

Project folder names may contain ASCII letters, numbers, hyphens, and underscores, but not spaces or paths. ManScript asks before continuing into an existing non-empty directory.

cd the-name-you-chose
manscript run

Scripts and CI may provide the stack and name directly:

manscript create django myproject
manscript create python utility
manscript create c hello
manscript create java sample

The global --yes or -y flag accepts confirmation prompts. It does not provide missing wizard answers in a non-interactive terminal.

What gets generated

  • Django: a Django project, pinned requirement, and commands for the development server and tests.
  • FastAPI: an application with Uvicorn and pytest commands.
  • Flask: an application with Flask development server and pytest commands.
  • Rails: a Rails project using SQLite, with run, test, and bin/rails assets:precompile build commands.
  • Sinatra: app.rb, a Gemfile, and a Ruby run command.
  • Language only: starter source files and suitable run/build commands for Python, Ruby, C, C++, or Java.

All variants include manscript.toml, a project environment under .manscript/environment, and ManScript entries in .gitignore.

Generate inside a project

Run from the project root or a child directory. Python app and module names for Django, Flask, and FastAPI cannot contain hyphens; use letters, numbers, and underscores. Django model names must start with a letter and use letters, numbers, or underscores.

Single-kind generators are shorter

Flask, FastAPI, and Sinatra have one generator kind, so ManScript skips the kind prompt and asks only for a name. Django defaults a single name to app; Rails still needs a kind because it offers four.

Django and Rails generators require a prepared project environment. Run manscript setup if it is missing.
